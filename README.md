## AI Assistant Setup

How I work with an AI coding assistant. Nine approaches, each with what it is and why.

**0. Commands, not guessed words.**
What: a message without a command is talk — the assistant answers in words and every edit is refused that turn. Work opens only on `/go`, and the answer starts with "understood as …". `/commit` and `/push` allow exactly one commit or push within ten minutes, never by a sub-agent. `/q`, `/iq`, `/redo`, `/stop`, `/fail`, `/win`, `/mem` cover questions, restating, stopping and the ledgers.
Why: hooks that guessed intent from words kept misreading — a question taken for an order, a picked option for a question. A typed command is read exactly; the session's first reply lists them.

**1. Rules are enforced by hooks, not by memory.**
What: a short core of rules loaded into every session, and small scripts on the assistant's events that refuse a step breaking a rule.
Why: a rule the model only remembers fails exactly when the context is longest. A refusal at the moment of the slip does not depend on attention.

**2. "Done" needs proof.**
What: no "done" without a run after the last edit; numbers are recounted by a script; claims about a library are checked by an experiment in a container.
Why: the most expensive mistake is the confident one. A check costs seconds; a wrong "done" costs a lost evening.

**3. Every slip is written down, in my words.**
What: a ledger of failures, each with the owner's verbatim reaction, grouped into classes and shown before every reply; a separate ledger of what the owner explicitly approved — a line appears only on my `/win`, in my words, and each one names the proof (a test with a planted break, a live run, a number), see the post `https://panov.id/blog/pobeda-eto-dokazatelstvo.html`.
Why: the same mistake comes back in a new shape. A list of my own patterns, in front of me every turn, catches the shape instead of the instance.

**4. A second opinion before it reaches me.**
What: a read-only judge agent checks every draft against the failure classes; a large piece goes through a panel of independent reviewers with a mandatory security lens, and every finding is first attacked by another agent.
Why: one reviewer has one set of blind spots. Findings that survive an attempt to refute them are the ones worth my time.

**5. Checked against the task, not only against the rules.**
What: at the end of each turn a cheap model compares what was done with my last message; a short message must be restated as "understood as …"; a change touching several files is first retold by a second agent.
Why: work that drifts to a neighbouring problem passes every quality check — it is good work on the wrong thing.

**6. A working memory the assistant queries itself.**
What: a small local database the assistant queries instead of grepping files: my messages and corrections, decisions, the rules, skills, docs and review notes, per project. It answers "was this already decided?", "where did I slip on this file?", and a new session starts from "where did we stop?" — the last turns in my own words.
Why: asking me what I already answered, or repeating a fixed mistake, costs more than a lookup. Command output never goes in, so no secrets.

**7. A map of the project instead of searching it.**
What: a generator — shared, or the project's own where its stack needs one — draws what links to what — code, database, documents — checks every link against the disk while building, and writes a diff to a journal when something changes.
Why: searching the code anew every session is slow and misses links. A map built from the project itself and checked on every build can be read in a minute and trusted.

**8. Cheap work goes to cheap models; the decision stays with me.**
What: mechanical steps with a machine check go to small executor agents; noisy output is read through a 12-line digest; I am asked only about money, accounts, irreversible actions and product forks — never about technique.
Why: tokens and my attention are the two scarce resources. Everything else the assistant decides, writes down, and reports with numbers.

Everything runs locally, nothing is installed on the host outside containers, and the setup lives in `~/.claude`.
